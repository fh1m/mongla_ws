# How the docs stay true — the wiki, the files, and the guards

This project's worst defect is a plausible number standing in for a missing measurement.
Documentation can make the same mistake: a page that was right when it was written and is
still read after the code moved. This page explains where the documents live, how you edit
them, and what fails when one of them stops being true.

## Where to read and edit

**In the [wiki](https://github.com/fh1m/mongla_ws/wiki).** The book is its sidebar, each chapter
is one page, and every page has an edit button. Use it the way you would use any wiki.

Each wiki page is also a file in this repository: the book under `.claude/context/`, and the two
long-form documents the site serves, `docs/the-shift.md` and `docs/capability-map.md`. The two
copies are kept the same by [`.github/workflows/wiki.yml`](../../../.github/workflows/wiki.yml):

| you do this | what happens |
|---|---|
| edit a page in the wiki | the page is turned back into its file, the doc guards below run, and the change is committed to `main` under your name |
| …and it breaks a guard | nothing reaches `main`. A branch and a pull request say what failed; the edit stays in the wiki |
| create a page in the wiki | it lands in `.claude/context/wiki/`. Link it from Home (the book), or the contract guard fails: a page nobody can reach is lost |
| push to `main` | the wiki is rebuilt from the files, so a code change and its documentation still land in one commit |
| delete a page in the wiki | **nothing.** GitHub does not report deletions. Delete the file in the repository; the page goes with it |

Only someone with write access to the repository gets a wiki edit committed. Anyone else's edit
stays in the wiki and the workflow says why.

The conversion is [`tools/wiki_build.py`](../../../tools/wiki_build.py). Links between documents
become wiki links, links to code point at the file on GitHub, and a generated footer is added
to each page. Pulling an edit back undoes exactly that. A test builds every page and pulls it
back, and fails if any page comes back different from its file. Without that test, an edit to
one line could quietly rewrite the others.

## What fails when a document stops being true

| guard | it fails when |
|---|---|
| `test_docs_contract.py` | a document is not reachable from the book; a chapter is listed under a title that is not its own first heading; a relative link points at nothing |
| `test_doc_drift.py` | a document states a constant (a firmware revision, a threshold) the code no longer holds |
| `test_the_retired_stack_stays_retired.py` | any tracked file still describes the earlier stack (tag `last-with-pixhawk-and-sim`) as if it were live |
| `test_operator_commands_are_real.py` | a document tells an operator to type a command, argument or launch file that does not exist |
| `test_the_wiki_is_built_from_the_book.py` | a wiki page links to no page, or does not round-trip to its file, or names a path on this machine |
| `test_published_test_counts_are_the_last_run.py` | a test count, package size or chapter count on the README or the site was typed by hand |

The editor hook runs the contract, retired-stack and wiki guards on every documentation edit.
The wiki workflow runs all of them except the operator-commands check, which needs ROS.

## Numbers nobody types

Three kinds of document are generated, so they cannot drift:

- **[`commands.md`](commands.md)** — every verb, field and default, every executable, launch
  argument, node parameter and wire constant. Regenerate it with `python3 tools/gen_reference.py`;
  a test fails if it is out of date.
- **[`bringup.example.yaml`](../../../src/mongla_manager/config/bringup.example.yaml)** — the
  settings template, generated by the same tool.
- **the published counts.** Every full test run (`python3 -m pytest -q` from the workspace root)
  writes [`docs/stats.json`](../../../docs/stats.json): tests per suite, lines of code and test files
  per package, chapters in the book. [`tools/published_counts.py`](../../../tools/published_counts.py)
  copies those numbers into the README and the site. A run of a single file never overwrites them.
  A run with failures publishes them in red.

## When you remove something

A removal is finished when every document that names the removed thing says what is true now.
On 2026-11-06 a backend was deleted in one commit and **53 files** went on describing it. The
retired-stack guard exists because of that day.
