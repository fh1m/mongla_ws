# The flashing procedure picks Bluejay 24 kHz (README) or 48 kHz (ESC_FLASHING.md): both put thruster PWM noise in or next to the pinger bands, and the doc is a copy of the one in srot-control-board

Part of the 2026-09-24 ecosystem review, round 2 (see ../README.md). Companion-side tracking: fh1m/mongla_ws#45. Board-side twin: srot-control-board draft 35 in this batch.

## Summary
This repo owns the ESC flashing procedure, and the procedure fixes the Bluejay PWM frequency.
- `src/esp32_4way/README.md:63` flashes **24 kHz**. That fundamental sits in the 20–25 kHz thruster ego-noise band the companion plans around, and its **2nd harmonic (48 kHz) is 3 kHz from the SAUVC 45 kHz pinger**.
- `docs/ESC_FLASHING.md:99-100` recommends **48 kHz** (fundamental 3 kHz from the SAUVC pinger), with 24 kHz as the fallback.
- Bluejay also builds **96 kHz** for the BB21 (`H`) MCU class, which is above both pinger bands. It costs PWM resolution, and the doc's own dead-time caveat (`ESC_FLASHING.md:175-178`) means it needs a bench check before it is adopted.

The two files give different answers. `docs/ESC_FLASHING.md` is also **byte-identical** to `srot-control-board/docs/ESC_FLASHING.md`: two copies of one document, which will drift.

## Failure scenario
The team fits a hydrophone for the 50-point SAUVC drum task. The ESCs were flashed by following this repo's README, at 24 kHz. Under thrust, eight thrusters put a harmonic line at 48 kHz, 3 kHz from the pinger. The acoustic front end has to notch next to its own signal, or the vehicle has to stop to listen. Nobody traces the noise back to a flashing choice, because no document connects the two.

## Suggested fix
- Pick the frequency from a bench comparison (24 / 48 / 96 kHz on one T200: start threshold, desync under a step, ESC temperature, and the 20–50 kHz spectrum if a hydrophone or wideband mic is available), as described in srot-control-board draft 35. Write the chosen frequency **and the reason** into the procedure.
- Make the README and `ESC_FLASHING.md` state the same frequency. Better, have the README link to the one recommendation instead of restating it.
- Keep **one** `ESC_FLASHING.md` (this repo owns the procedure) and replace the srot-control-board copy with a link, or add a CI check that the two are identical.
