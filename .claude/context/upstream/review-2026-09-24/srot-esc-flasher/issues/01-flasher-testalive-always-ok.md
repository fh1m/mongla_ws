# InterfaceTestAlive ignores the ESC's reply and always ACKs OK, so a dead or disconnected ESC looks alive to esc-configurator

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
The `cmd_InterfaceTestAlive` (0x30) handler sends `CMD_KEEP_ALIVE` to the ESC and reads the reply. The lines that would set a failure ACK are commented out, so the response always carries the default `ACK_OK`. esc-configurator uses this keep-alive to decide that the ESC session is still up. With an unplugged, unpowered or crashed ESC, the tool carries on as if it were connected.

## Evidence
At commit `c30b843`, `src/esp32_4way/4Way.cpp:231-253`:
```cpp
  else if (cmd == cmd_InterfaceTestAlive) {
    O_Param_Len = 0x01;
    uint8_t ESC_data[2] = {CMD_KEEP_ALIVE, 0};
    ...
    RX_Size = SendESC(ESC_data, Data_Size);
    RX_Size = GetESC(RX_Buf, 20);
    ...
    if (RX_Size != 0 && RX_Buf[0] == brSUCCESS) {
      //buf[6] = ACK_OK;    // ACK
    }
    else {
      //buf[6] = ACK_D_GENERAL_ERROR;    // ACK
    }
  }
```
`:101` resets `ack_out = ACK_OK;` for every command. `:579` emits `buf[O_Param_Len + 5] = ack_out;`. Nothing in this branch changes `ack_out`. Note that the commented-out code wrote `buf[6]`; the other handlers now use `ack_out` instead.

## Failure scenario
1. The operator connects esc-configurator through the flasher, reads ESC 3, and then the ESC browns out, or its signal wire comes loose while the vehicle is handled.
2. esc-configurator's periodic keep-alive keeps receiving `ACK_OK`, so the UI shows the ESC as connected.
3. The operator clicks "Write settings" or "Flash". The first real command fails part-way, or, together with srot-esc-flasher #1 (a failed SET_ADDRESS does not abort), goes further than it should before an error appears.
4. There is also no liveness signal: a bench check such as "are all 8 ESCs answering?" run through this interface always passes.

## Suggested fix
```cpp
    if (RX_Size != 0 && RX_Buf[0] == brSUCCESS) {
      ack_out = ACK_OK;
    } else {
      ack_out = ACK_D_GENERAL_ERROR;
    }
```
Also check `Enable4Way` first, and return `ACK_D_GENERAL_ERROR` when it is not active, as `cmd_DeviceReset` does.

## How to verify
- **Bench:** connect esc-configurator and read one ESC, then unplug that ESC's signal wire. Within one keep-alive period the tool must report the ESC as disconnected. Today it does not.
- Use the `t` key in the serial debug menu (`main.cpp:44`) with the ESC unplugged: the reply byte must be `ACK_D_GENERAL_ERROR` (0x0F).
- **Injection test:** comment the two `ack_out` assignments back out and confirm the unplug test passes silently again.

## Severity: Medium
A liveness check that cannot fail lets flash and write operations start against a dead ESC. It is a bench tool, so there is no in-water risk.
