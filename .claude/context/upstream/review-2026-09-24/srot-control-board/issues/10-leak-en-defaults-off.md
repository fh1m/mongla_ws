# LEAK_EN defaults to 0: leak sensing, the leak pre-arm and the leak failsafe are all off by default, and a disabled sensor reports "dry"

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
`LEAK_EN` defaults to 0. With it at 0:
- the leak pin is not read
- the pre-arm leak check is skipped
- the leak failsafe never trips
- telemetry reports the hull as **dry** (`NAMED_VALUE_FLOAT LEAK = 0` and the `SYS_STATUS` extended health bit set = healthy) instead of "unknown".

After any defaults reset (see the FRAME_REVERSE issue in this batch), a vehicle that has never been in water dives with no leak protection, and the telemetry says it is dry.

## Evidence
At commit `f1d3ba9`.

`src/comms/params.cpp:144`:

```
`src/drivers/analog_mon.cpp:64`: disabled means `leak=false`.

```
`src/control/arming.cpp:37` and `src/tasks/task_control_loop.cpp:641` are both gated on `leak_en`.

## Failure scenario
1. A board is freshly flashed, or its NVS is reformatted, or `PARAM_DEFAULTS_VER` is bumped. `LEAK_EN` becomes 0.
2. The vehicle arms and dives. Water enters through a penetrator.
3. The leak probe is wet, but the pin is never read. No pre-arm refusal, no failsafe `SURFACE`, no STATUSTEXT.
4. The companion reads `LEAK=0.0` and the `SYS_STATUS` leak health bit is set (healthy). Unless it also checks the `enabled` word, the companion reports "dry" with confidence.

## Suggested fix
This is a policy call for the firmware lead, so here are two options:
- **(a) Default to on:** `LEAK_EN = 1`. The pin has no internal pull (`analog_mon.cpp:23`), so shipping this needs the external bias fitted, or a pre-arm "leak input floating" detection.
- **(b) Keep the default off, but make it loud:** `canArm()` refuses with `"LEAK_EN=0 - set 1 or LEAK_WAIVE=1"` unless an explicit waiver param is set, and the waiver resets on each boot.

Either way, **report absence as absence.** When `LEAK_EN=0`, do not send `NAMED_VALUE_FLOAT LEAK` at all, or send NaN. Clear the bit in `ext_health` as well as in `ext_enabled`, so that a consumer reading only health does not see "dry".

## How to verify
- Flash with an erased NVS and try to arm. With (b), arming is refused with the reason. With (a), shorting the leak input refuses arming.
- With `LEAK_EN=0`, `connect --watch` shows `LEAK` as `--`, not `0`.
- **Injection test:** reintroduce `sendNamed("LEAK", 0)` while disabled and confirm a host test ("LEAK absent when disabled") fails.

## Severity: Medium
It is a one-line default, but it silently removes the only flood protection on a vehicle that has never been wet, and the telemetry says "dry".
