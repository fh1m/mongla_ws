# Proposal: an on-board vertical state estimator (baro + IMU vertical acceleration, a 2-state Kalman filter)

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
Today the depth loop sees a raw 20 Hz baro depth held at 500 Hz. The D-term differentiates that step signal (a separate issue), and any baro dropout makes depth invalid within 1.5 s. A standard 2-state filter with states `[z, w]` (depth and vertical velocity) predicts at 500 Hz from the IMU's gravity-removed vertical acceleration and corrects at the baro rate. It gives the depth loop a smooth vertical velocity for damping. It bridges short baro gaps with an honest, growing uncertainty. It also gives the companion a vertical-velocity telemetry value that it has no way to get today.

## Evidence
At commit `f1d3ba9`.
- `src/tasks/task_sensor_read.cpp:41` sets the baro at about 20 Hz, and `task_control_loop.cpp:188` runs depth every 2 ms on the held value.
- `include/config.h:618`: `DEPTH_STALE_MS 1500`. After that, depth is withdrawn and `DEPTH_HOLD` and `AUTO` are refused.
- `LINEAR_ACCELERATION` is not enabled (`bno085.cpp:89-99`), so the prediction input has to be added: either enable that report, or rotate raw acceleration by the game quaternion and subtract g.

## Proposal
```
state x = [z, w]      (m, m/s; z positive down)
predict (500 Hz):  z += w*dt + 0.5*a_z*dt²;  w += a_z*dt;   P = F P Fᵀ + Q(σ_a)
correct (on each new baro sample, real Δt): y = z_baro - z;  S = P00 + R;  K = P[:,0]/S; x += K*y; P = (I - K H) P
```
- About 20 flops per tick: negligible on the ESP32 and deterministic.
- Add an accelerometer-bias state if drift demands it (3-state).
- Outputs:
  - `z` and `w` go to the depth PID, with `w` as the D input so the PID stops differentiating.
  - A `depth_sigma` value: withdraw depth when σ exceeds a threshold, instead of using a fixed 1.5 s timeout.
  - `w` goes out as telemetry (`NAMED_VALUE_FLOAT VZ`, or `VFR_HUD.climb`, which is hard-coded to 0 today).
- Gate the correction with an innovation check (reject |y| > 5σ), so a single bad baro sample cannot jolt the loop.

## How to verify
- **Offline:** replay a recorded baro and IMU log from a bucket or pool test. `w` must match a smoothed central difference of `z` without the 20 Hz sawtooth. Blank the baro for 1 s: `z` must drift by less than 5 cm and σ must grow.
- **Bench:** raise and lower the sensor in a water column by a known 0.3 m. `z` must track to ±1 cm, and `w` must integrate back to 0.3 m.
- **In water:** depth-hold step responses with D fed from `w`. Compare overshoot and settling with the current loop.

## Severity: Proposal
A standard, cheap addition that fixes the depth D-term issue properly and makes depth robust to dropouts.
