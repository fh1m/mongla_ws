# VFR_HUD.alt carries a held or never-measured depth when the baro is invalid or stale (the companion's depth feed)

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
`SCALED_PRESSURE2` and `WTEMP` are suppressed when `depth_ok` is false. `VFR_HUD` is sent unconditionally, with `alt = -s.depth`, and `s.depth` is the **last** successful Bar30 sample, or 0 if there has never been one. The companion reads depth from `VFR_HUD`. When the baro dies, it keeps receiving a plausible, frozen depth. This was flagged in `DOC_DRIFT_AND_DESIGN_REVIEW_2026-08-03.md` §5 on 2026-08-03 and is still unfixed at `f1d3ba9`.

## Failure scenario
1. At 2.0 m the Bar30 stops answering because of an I2C fault, a flooded port, or the IMU-heal starvation described in a separate issue.
2. `depth_ok` becomes false. The board withdraws baro health from `SYS_STATUS` and stops sending `SCALED_PRESSURE2`.
3. `VFR_HUD.alt` keeps reporting −2.00 at the stream rate. Any consumer that reads depth without cross-checking the `SYS_STATUS` health bit (logging, Foxglove, a new mission, Bondor's HUD) sees a vehicle holding 2.00 m perfectly while it actually sinks or rises.
4. On a board with no Bar30 fitted, `alt` is `-0.000` forever. At the surface that is a confident value, and it disables every "deeper than X" guard.

The mongla host already guards on the health bit, which is why this is Medium and not High. But the host's own rule is that a plausible number standing in for an absent measurement is the recurring defect.

## Suggested fix
`VFR_HUD` has no validity field, so send NaN for `alt` when depth is invalid. MAVLink permits this, pymavlink decodes it, and QGC renders it as "--":
```cpp
const float alt = s.depth_ok ? -s.depth : NAN;
mavlink_msg_vfr_hud_pack(..., (uint16_t)s.throttle_pct, alt, 0.0f);
```
Heading and throttle stay valid, so the message itself should keep flowing. Document the change in `JETSON_COMMS.md`, and bump the behaviour revision so the host can depend on it.

## How to verify
- **Bench:** unplug the Bar30. Within 1.5 s `VFR_HUD.alt` must read NaN, which shows as `--` in `connect --watch`. Plug it back in and a number must return.
- **Injection test:** remove the `depth_ok` ternary and confirm that a host test asserting NaN-on-unplug fails.

## Severity: Medium
The companion's depth feed reports a stale value as live. It is mitigated only because the current host cross-checks health.
