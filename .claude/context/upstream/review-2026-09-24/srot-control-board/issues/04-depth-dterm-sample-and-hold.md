# The depth D-term differentiates a 20 Hz sample-and-hold baro at 500 Hz (the raw derivative spikes 25×)

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
The Bar30 is read at about 20 Hz. The depth PID runs at 500 Hz on the held value. Its derivative-on-measurement is therefore 0 for 24 cycles, and on the 25th cycle it is `Δdepth/0.002 s`, which is 25 times the true rate. The 20 Hz one-pole D filter reduces that impulse to a peak of about 5× the true rate followed by a decay to 0, repeating every 50 ms. Baro noise reaches D with a gain of 500 instead of 20. This is the likely reason `DEPTH_D` had to be cut from 0.2 to 0.01 in the water.

## Evidence
At commit `f1d3ba9`.

`src/tasks/task_sensor_read.cpp:41-44` and `:69-72`: the baro is decimated from the 500 Hz sensor task.
```cpp
    const uint16_t BARO_DIV  = TASK_SENSOR_HZ / 20;   // ~20 Hz when healthy
    ...
        if (++baro_cnt >= baro_div) {
            baro_cnt = 0;
            baro_new = bar30::read(baro, baro_zero);
```
`src/tasks/task_control_loop.cpp:275` and `:188`: the loop uses a fixed `dt` and runs depth every cycle.
```cpp
    const float dt = CONTROL_LOOP_DT;
    ...
            thr = depth::update(in.sp_throttle, in.depth, dt, tgt);
```
`src/control/pid.h:71-84`: the derivative is taken on every call.
```cpp
        float d_raw = 0.0f;
        if (!_first) d_raw = -(measurement - _prev_meas) / dt;
        _prev_meas = measurement;
        const float fc = (_fltd >= 0.0f) ? _fltd : ((PID_D_FILT_HZ > 0.0f) ? (float)PID_D_FILT_HZ : 0.0f);
```
The depth PID never calls `setFilters()`, so it uses `PID_D_FILT_HZ = 20.0f` (`include/config.h:382`). With dt=2 ms that gives α≈0.20: the first-cycle response is 0.2×25 = 5× the true rate, with a time constant of about 8 ms.

The comment beside `DEF_DEPTH_D` in `include/config.h` records the symptom: "D 0.2 was 20x too strong and the operator brought it to 0.01".

## Failure scenario
1. The vehicle descends at 0.2 m/s. Each new baro sample is 1 cm deeper than the last.
2. On the cycle a sample arrives, `d_raw` = 0.01/0.002 = 5 m/s, and the filtered D is about 1 m/s, 5× the truth. It falls back to about 0 within the next 50 ms.
3. With `DEPTH_D=0.2` that is a throttle pulse of about ±0.2 at 20 Hz, which is audible and visible as buzzing. Baro quantisation noise (about 2 mm at the default OSR) goes through the same factor of 500.
4. The operator's fix was to lower D 20×. The loop now has almost no damping. The derivative is correct on average but is delivered as a 20 Hz impulse train, so the loop cannot use it.

## Suggested fix
Pick one:
- **Minimum:** compute the depth rate only when a sample is new, using the real Δt between samples (from `baro_stamp_ms`). Hold that rate between samples and pass it to the PID as an explicit rate input, so the PID is not differentiating a held value. Add a `PID::update(sp, meas, meas_rate, dt)` overload, or `setDerivative()`.
- **Better:** a 2-state vertical filter (depth and vertical velocity) that predicts with IMU vertical acceleration at 500 Hz and corrects with the baro at 20 Hz. It gives a smooth velocity for the D-term and bridges baro dropouts. See the separate proposal "on-board vertical state estimator".

**Correction to the audit that raised this:** `LINEAR_ACCELERATION` is **not** enabled today. `bno085.cpp:89` explains why it was dropped, and `enableReportsChecked()` at `:95-105` enables only GAME_ROTATION_VECTOR, GYROSCOPE_CALIBRATED and GRAVITY. `SensorState.lin_accel` is therefore never fed. The filter option needs an acceleration report enabled, or it can use gravity-compensated raw acceleration. Both add I2C traffic on the bus that already has the BNO085 reset history.

After either fix, retune `DEPTH_D` upwards from 0.01 in the water. It should settle much closer to the originally reasoned 0.2.

## How to verify
- **Bench, log only:** stream `DEPTH_OUT` together with the D term, at least 100 Hz over USB. Move the vehicle slowly in a bucket or pressure chamber. Today D is a 20 Hz sawtooth. After the fix it is continuous.
- **Unit test:** feed a 0.2 m/s ramp that is sampled at 20 Hz and held at 500 Hz. The peak |D| must be within ±20 % of 0.2 m/s. Today it is about 1.0.
- **Injection test:** remove the new-sample gate and confirm the test fails.
- **Water:** step response of `set_depth` with D at 0.05, 0.1 and 0.2. Record the overshoot.

## Severity: High
The depth loop's only damping term is unusable as built, and the depth loop has never run closed in water.
