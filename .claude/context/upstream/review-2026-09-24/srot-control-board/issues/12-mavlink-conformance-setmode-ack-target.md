# MAVLink conformance: SET_MODE is never ACKed and can fail silently, target_component is ignored, COMMAND_ACK is addressed to 0/0, and SYS_STATUS link errors are always 0

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
There are four small wire-contract gaps. On the host they add up to "`set_mode` is best-effort; a silent refusal looks exactly like success".
1. `SET_MODE` (msg 11) gets no response. An unsupported mode is dropped silently, and a mode change lost to a mutex timeout still counts as success. This also affects `DO_SET_MODE`, which ACKs `ACCEPTED`.
2. `COMMAND_LONG`, `COMMAND_INT` and `PARAM_SET` check `target_system` but not `target_component`, and `SET_MODE` checks neither.
3. `COMMAND_ACK` is packed with `target_system=0` and `target_component=0`, so every station on a shared link treats every ACK as its own.
4. `SYS_STATUS.drop_rate_comm` and `errors_comm` are hard-coded to 0, and parser drops are never counted.

## Failure scenario
1. The host sends `SET_MODE STABILIZE` to leave `AUTO` after a move (see #15). Core 1 holds `mtx_control` long enough for the 20 ms default timeout to expire. The mode is not changed and nothing is reported. The host's own read-back is the only defence, and it needs a HEARTBEAT round trip.
2. Bondor and the companion share the board. The companion sends `COMMAND_LONG ARM`, and Bondor, which is waiting on its own `DO_SET_SERVO`, receives an ACK addressed to 0/0 with a different command id. A retry loop that matches on `command` alone completes or fails on the wrong ACK.
3. At 115200 on a busy link (#17), CRC drops go unseen. The host cannot tell "the board ignored me" from "the frame was corrupted".

## Suggested fix
- `onSetMode`: check `sm.target_system`. Call `setMode()` and send `COMMAND_ACK(command=MAV_CMD_DO_SET_MODE, result)`. ArduPilot does exactly this for msg 11. On an unsupported mode, also send `STATUSTEXT "mode N refused"`.
- `setMode()`: return `lk.ok()` when the lock was not taken, and map that to `TEMPORARILY_REJECTED`.
- Ignore commands whose `target_component` is neither 0 nor `MAV_COMPONENT_ID`.
- `ackCommand(cmd, res)`: pass `s_cmd_src_sys` and `s_cmd_src_comp` as the ACK's target fields.
- Keep `status.packet_rx_drop_count` and parse errors in statics. Report `errors_comm` and a `drop_rate_comm` (in centi-percent) computed over a 1 s window.

## How to verify
- **pymavlink bench:** `set_mode_send(target=1, custom_mode=99)` must return `COMMAND_ACK DENIED`, and `custom_mode=0` must return `ACCEPTED`.
- Send `COMMAND_LONG` with `target_component=250` and expect no action and no ACK.
- The ACK must carry `target_system` and `target_component` equal to the sender's.
- Inject 100 corrupted bytes and watch `SYS_STATUS.errors_comm` increase.
- **Injection test:** remove the SET_MODE ACK and confirm the host's `set_mode` verify test fails.

## Severity: Medium
There is no single catastrophic case, but these gaps are why the host cannot trust mode changes or tell link loss from refusal.
