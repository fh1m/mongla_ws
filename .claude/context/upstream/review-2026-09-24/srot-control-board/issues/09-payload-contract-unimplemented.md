# Payload channels survive disarm and every failsafe, pca9685_aux::healthy() cannot fail, and there is no PAYLOAD_FIRE command (TASKS §7, still open)

Part of the 2026-09-24 ecosystem review (tracking issue in fh1m/mongla_ws, link to follow).

## Summary
`TASKS_FROM_DUBURI_WS.md` §7 (added 2026-08-03) asked for three things:
- a dedicated fire command, §7A
- failsafes that de-energise payload channels, §7B
- a health probe that can fail, §7C

At `f1d3ba9` none of them is implemented. A MOSFET or solenoid channel switched on by `DO_SET_RELAY` or `DO_SET_SERVO` **stays energised through disarm, leak, GCS loss and SURFACE**. `pca9685_aux::healthy()` returns true even when the chip is unplugged.

## Evidence
At commit `f1d3ba9`.

- `grep -rn "31001\|PAYLOAD_FIRE" src include` returns nothing, so §7A is absent.
- The only writers of `g_state.aux.switch_on[]` are `mav_commands.cpp:196` (`setRelay`), `:497` (`DO_SET_SERVO`) and `:511` (`DO_SET_RELAY`). Nothing in `task_control_loop.cpp`, `arming.cpp` or the failsafe or disarm paths touches `AuxState` (`grep -rn "g_state.aux" src`).
- `src/drivers/pca9685_aux.cpp:13-21` and `:48`:
```cpp
bool begin(TwoWire* wire) {
    static Adafruit_PWMServoDriver pwm(I2C_ADDR_PCA9685, *wire);
    s_pwm = &pwm;
    s_pwm->begin();
    s_pwm->setOscillatorFrequency(27000000);
    s_pwm->setPWMFreq(PCA9685_PWM_FREQ);
    s_ok = true;
    return s_ok;
}
...
bool healthy() { return s_ok; }
```
- `task_ui_status.cpp:116-123` does probe the chip at 1 Hz (`pca_present`), but only for the OLED. It does not feed `healthy()`, telemetry or the command ACKs.

## Failure scenario
1. On the bench the operator fires a gripper or dropper solenoid with `DO_SET_RELAY` and forgets to release it. The same happens if a mission aborts between "on" and "off".
2. The vehicle disarms, or a leak or GCS-loss failsafe surfaces and auto-disarms it.
3. The channel stays energised. At the surface, a person reaching in to recover the vehicle meets a live gripper, dropper or torpedo actuator, and the coil keeps heating.
4. If the PCA9685 is unplugged, `DO_SET_RELAY` still returns `ACCEPTED`. It also returns `ACCEPTED` when `mtx_aux` could not be taken and nothing was written (`mav_commands.cpp:510-512`). The host reports FIRED and nothing happened.

## Suggested fix
- **§7B, the priority, a few lines:** add `aux_safe_all()`, which clears every channel with role `PCA_SWITCH` and sets `dirty`. Call it on the disarm edge, on the failsafe latch (leak, battery, GCS, companion) and on `SURFACE` entry. Announce it with `STATUSTEXT "payload channels de-energised"`.
- **§7C:** set `s_ok` from a `MODE1` read-back in `begin()`. Feed the existing 1 Hz `pca_present` probe into `s_ok`. `DO_SET_RELAY` and `DO_SET_SERVO` return `MAV_RESULT_FAILED` when `!healthy()`. Report the state as a `NAMED_VALUE_FLOAT AUXOK` or a `SYS_STATUS` bit.
- **§7A:** the dedicated `MAV_CMD_SROT_PAYLOAD_FIRE`, with pulse width and role checks, as specified in the TASKS doc. Note that id 31001 is allocated twice (PR #2), so settle the id first.

## How to verify
- **Bench (props off, solenoid or LED on channel N):** `DO_SET_RELAY N 1`, then disarm, and the channel must go off within one UI tick of 33 ms. Repeat with a forced leak (`LEAK_EN=1`, short the input) and with GCS loss.
- Unplug the PCA9685 and send `DO_SET_RELAY`: the ACK must be `FAILED`.
- **Injection test:** remove the `aux_safe_all()` call from the disarm path and confirm the bench check fails.

## Severity: Medium
A live payload channel that survives disarm is a hand-safety hazard at recovery. A fake FIRED is a mission-scoring failure.
